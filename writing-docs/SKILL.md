# Writing documents in my voice (tech specs, Notion)

- **Structure per section**: a short intro paragraph (1-3 sentences), then
  bullets.
- **Flows**: a mermaid diagram where a flow has dependencies, and an FAQ
  section with bold questions at the end.
- **Section skeleton** I reuse: Problem, Product Requirements, High-Level
  Technical Solution, Implementation Details, Project Breakdown (milestones
  where bullets map to tickets), Rollout Plan, FAQ.
- **Notion callouts**: 🎯 blue for the TL;DR/core idea, 💡 gray for "why this
  choice" asides, 🔒 gray for a hard guarantee, ⚠️ yellow for
  accepted-risk/deferral flags, 👀 gray for stance statements a skimmer must
  catch. Callouts are for asides and flags, not load-bearing explanation.
  Don't stack adjacent callouts. Reading aids like legends stay inline.
- **Each version stands alone**: remove references that only make sense
  against an earlier draft ("there is no longer X").
